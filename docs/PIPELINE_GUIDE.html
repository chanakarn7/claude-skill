Big builds

How roadmap scales to many modules

Shared decisions are locked once at the program level; each module is then scoped just-in-time as its sprint begins.

Locked once — shared
docs/program/
  • VISION.md
  • ARCHITECTURE.md
  • DATA_MODEL.md
  • DESIGN_SYSTEM.md
  • ROADMAP.md
Per module — just-in-time
docs/modules/<name>/
  • PRD.md
  • SA_BLUEPRINT.md
  • UXUI_DESIGN.md
  • … one /kickoff run each
The Entity Catalog at the top of DATA_MODEL.md lets a late module read only the tables it touches — so module 11 costs no more to scope than module 2. Schema evolves through additive migrations, never destructive rewrites.
Which one do I use?
Several distinct modules whose data flows together, shipped across sprints → /roadmap. One coherent project → /kickoff. A single doc or component → a specialist skill directly. The skills self-route, so just start anywhere.
