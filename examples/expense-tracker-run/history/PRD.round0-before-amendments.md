## 1. Overview
**Problem.** ผู้ใช้อยากจดรายรับรายจ่ายประจำวันของตัวเองอย่างรวดเร็วบนมือถือ และรู้ว่าเดือนนี้รับเท่าไร จ่ายเท่าไร เหลือเท่าไร โดยไม่ต้องสมัครสมาชิกหรือพึ่ง server

**Target users.** บุคคลทั่วไปคนเดียว (ผู้ใช้ภาษาไทย) ที่จดเงินของตัวเอง ใช้บนมือถือเป็นหลัก

**Platform.** เว็บแอปฝั่ง client ล้วน (single-page app, mobile-first, ใช้บน desktop ได้) เก็บข้อมูลใน browser ของเครื่อง (localStorage) ไม่มี backend ไม่มี login UI ภาษาไทยทั้งหมด สกุลเงินบาท (THB)

**Goals.**
- เพิ่มรายการใหม่ได้ภายใน ~10 วินาที (เปิดฟอร์ม → กรอกจำนวน + หมวด → บันทึก)
- เห็นยอดรวมรายรับ รวมรายจ่าย และยอดคงเหลือของเดือนที่เลือกทันทีที่เปิดแอป
- ดูรายการย้อนหลังรายเดือนและกรองตามหมวดหมู่ได้
- แก้ไข/ลบรายการได้
- ข้อมูลคงอยู่หลังปิด/เปิด browser ใหม่

**Non-goals (OUT of scope).**
- หลายผู้ใช้, บัญชีผู้ใช้, login, สิทธิ์การเข้าถึง
- sync ข้ามเครื่อง, cloud backup, server/API ใดๆ
- export/import (CSV, Excel, PDF), พิมพ์รายงาน
- กราฟซับซ้อน (line/pie แบบโต้ตอบ, เทรนด์หลายเดือน) — มีเพียงแถบสัดส่วนรายจ่ายตามหมวดแบบเรียบง่าย (US-11)
- งบประมาณ (budget), รายการประจำ/ซ้ำอัตโนมัติ, แจ้งเตือน
- หลายสกุลเงิน, หลายบัญชี/กระเป๋าเงิน
- สร้าง/แก้ไข/ลบหมวดหมู่เอง (MVP ใช้หมวดหมู่ตั้งต้นคงที่ — ดู §5)
- ค้นหาด้วยข้อความ (search) ในโน้ต
- เชื่อมต่อธนาคาร/payment ใดๆ
- PWA offline install / service worker (แอปทำงานได้โดยไม่มีเน็ตอยู่แล้วหลังโหลดหน้า แต่ไม่ทำ installable PWA)

Prototype: skip — แอปมี 3 หน้าจอ (หน้าแรก, รายการย้อนหลัง, ฟอร์มเพิ่ม/แก้ไข) และ flow เรียบง่าย; การเลือก 3 แนวทางดีไซน์ทำในขั้น design ได้ (เปลี่ยนเป็น include ได้ที่ Gate 1)

## 2. User roles & permissions
| Role | Description | Permissions |
|---|---|---|
| ผู้ใช้ (Owner) | คนเดียวที่ใช้ browser/เครื่องนั้น | เพิ่ม ดู แก้ไข ลบ รายการทั้งหมดของตัวเอง |

ไม่มีการยืนยันตัวตน ใครก็ตามที่เปิด browser นั้นเห็นข้อมูลได้ (ระบุไว้ใน §7 Privacy)

## 3. User stories
หมายเหตุ: "เดือนที่เลือก" เริ่มต้นเป็นเดือนปัจจุบันตามนาฬิกาเครื่อง เวลาท้องถิ่น

**US-01 เพิ่มรายการ**
ในฐานะผู้ใช้ ฉันต้องการเพิ่มรายการรายรับหรือรายจ่าย เพื่อบันทึกการเงินประจำวัน
- Given ผู้ใช้อยู่หน้าใดก็ได้ When กดปุ่ม "เพิ่มรายการ" Then ฟอร์มเปิดขึ้น ประเภทเริ่มต้น = รายจ่าย, วันที่เริ่มต้น = วันนี้, จำนวนเงินว่าง, หมวดหมู่ยังไม่ถูกเลือก, โน้ตว่าง
- Given กรอกจำนวน 150, ประเภท รายจ่าย, หมวด อาหาร, วันที่วันนี้ When กด "บันทึก" Then ฟอร์มปิด รายการปรากฏในรายการของเดือนนี้ และยอดรวมรายจ่ายเพิ่มขึ้น 150.00
- Given เปลี่ยนประเภทจากรายจ่ายเป็นรายรับ When ดูตัวเลือกหมวดหมู่ Then แสดงเฉพาะหมวดของรายรับ และหมวดที่เลือกไว้เดิม (ถ้าไม่ใช่ของรายรับ) ถูกล้าง
- Given บันทึกสำเร็จ Then แสดงข้อความยืนยันสั้นๆ "บันทึกแล้ว" (toast) ไม่เกิน 3 วินาที

**US-02 ตรวจสอบความถูกต้องของข้อมูล**
- Given จำนวนเงินว่าง, เป็น 0, ติดลบ, หรือไม่ใช่ตัวเลข When กดบันทึก Then ไม่บันทึก และแสดงข้อความใต้ช่อง "กรุณากรอกจำนวนเงินมากกว่า 0"
- Given จำนวนเงินมีทศนิยมเกิน 2 ตำแหน่ง (เช่น 10.555) When กดบันทึก Then ไม่บันทึก และแสดง "ทศนิยมได้ไม่เกิน 2 ตำแหน่ง"
- Given จำนวนเงินเกิน 99,999,999.99 When กดบันทึก Then ไม่บันทึก และแสดง "จำนวนเงินสูงเกินไป"
- Given ไม่ได้เลือกหมวดหมู่ When กดบันทึก Then ไม่บันทึก และแสดง "กรุณาเลือกหมวดหมู่"
- Given วันที่ว่างหรือไม่ถูกต้อง When กดบันทึก Then ไม่บันทึก และแสดง "กรุณาเลือกวันที่"
- Given โน้ตยาวเกิน 200 ตัวอักษร Then ช่องโน้ตรับได้สูงสุด 200 ตัวอักษร และแสดงตัวนับ "n/200"
- Given มีข้อผิดพลาดหลายช่อง When กดบันทึก Then แสดงข้อความทุกช่องพร้อมกัน และโฟกัสไปที่ช่องแรกที่ผิด

**US-03 แก้ไขรายการ**
- Given มีรายการอยู่ When แตะรายการนั้นในลิสต์ Then ฟอร์มเปิดในโหมดแก้ไข หัวข้อ "แก้ไขรายการ" และกรอกค่าเดิมไว้ครบทุกช่อง
- Given แก้จำนวนจาก 150 เป็น 200 When กดบันทึก Then รายการแสดง 200.00 และยอดรวมอัปเดตตาม (ไม่เกิดรายการซ้ำ)
- Given แก้วันที่ไปเดือนอื่น When บันทึก Then รายการหายจากเดือนที่เลือกปัจจุบันและไปปรากฏในเดือนใหม่ ยอดรวมทั้งสองเดือนถูกต้อง
- Given อยู่ในโหมดแก้ไข When กด "ยกเลิก" หรือปิดฟอร์ม Then ไม่มีการเปลี่ยนแปลงข้อมูล

**US-04 ลบรายการ**
- Given อยู่ในฟอร์มโหมดแก้ไข When กด "ลบ" Then แสดงกล่องยืนยัน "ลบรายการนี้? ไม่สามารถกู้คืนได้" พร้อมปุ่ม "ลบ" และ "ยกเลิก"
- Given กล่องยืนยันแสดงอยู่ When กด "ลบ" Then รายการถูกลบ หายจากลิสต์ ยอดรวมอัปเดต และแสดง toast "ลบแล้ว"
- Given กล่องยืนยันแสดงอยู่ When กด "ยกเลิก" Then รายการยังอยู่เหมือนเดิม

**US-05 สรุปยอดของเดือนบนหน้าแรก**
- Given เดือนที่เลือกมีรายรับรวม 20,000 และรายจ่ายรวม 7,500.50 When เปิดหน้าแรก Then แสดง รวมรายรับ "฿20,000.00", รวมรายจ่าย "฿7,500.50", ยอดคงเหลือ "฿12,499.50"
- Given รายจ่ายมากกว่ารายรับ Then ยอดคงเหลือแสดงเป็นค่าติดลบมีเครื่องหมาย "−" (เช่น "−฿500.00") และใช้สีเตือน (ไม่อาศัยสีอย่างเดียว — มีเครื่องหมายลบ)
- ยอดคงเหลือ = รวมรายรับ − รวมรายจ่าย ของเดือนที่เลือกเท่านั้น (ไม่ยกยอดจากเดือนก่อน)
- Given หน้าแรก Then แสดงรายการล่าสุดของเดือนที่เลือกไม่เกิน 5 รายการ พร้อมลิงก์ "ดูทั้งหมด" ไปหน้ารายการย้อนหลังของเดือนเดียวกัน

**US-06 เลือกเดือน**
- Given อยู่หน้าแรกหรือหน้ารายการ When กดลูกศร "◀" / "▶" ข้างชื่อเดือน Then เปลี่ยนเป็นเดือนก่อน/ถัดไป และยอดรวม/รายการอัปเดตตามเดือนนั้น
- ชื่อเดือนแสดงเป็นภาษาไทยปี พ.ศ. เช่น "ตุลาคม 2569"
- Given เลือกเดือนในหน้าแรกแล้วไปหน้ารายการ (หรือกลับกัน) Then เดือนที่เลือกเป็นเดือนเดียวกัน (แชร์สถานะ)
- Given เปิดแอปใหม่ (reload) Then เดือนที่เลือกกลับเป็นเดือนปัจจุบัน
- ไม่จำกัดการเลื่อนไปเดือนในอนาคตหรืออดีต; มีปุ่ม "เดือนนี้" เพื่อกลับเดือนปัจจุบันเมื่อไม่ได้อยู่ที่เดือนปัจจุบัน

**US-07 ดูรายการย้อนหลังแยกตามเดือน**
- Given เดือนที่เลือกมีรายการ When เปิดหน้ารายการ Then แสดงทุกรายการของเดือนนั้น จัดกลุ่มตามวัน เรียงวันล่าสุดก่อน; ภายในวันเดียวกันเรียงตามเวลาที่สร้างล่าสุดก่อน
- แต่ละกลุ่มวันมีหัวข้อวันที่ภาษาไทย (เช่น "อ. 7 ต.ค. 2569")
- แต่ละรายการแสดง: ไอคอน/ชื่อหมวด, โน้ต (ถ้ามี ตัดด้วย … เมื่อยาว), จำนวนเงิน รายรับนำหน้าด้วย "+" รายจ่ายนำหน้าด้วย "−"
- Given รายการที่วันที่อยู่นอกเดือนที่เลือก Then ไม่แสดงในลิสต์

**US-08 กรองตามหมวดหมู่**
- Given อยู่หน้ารายการ When เลือกหมวด "อาหาร" จากตัวกรอง Then แสดงเฉพาะรายการหมวดอาหารของเดือนที่เลือก และแสดงยอดรวมของหมวดนั้น "รวม ฿x"
- ตัวกรองมีตัวเลือก "ทุกหมวด" (ค่าเริ่มต้น) และทุกหมวดทั้งรายรับและรายจ่าย จัดกลุ่มเป็น "รายจ่าย" / "รายรับ"
- Given ตัวกรองเลือกหมวดอยู่ When เปลี่ยนเดือน Then ตัวกรองยังคงเดิม
- Given ตัวกรองแล้วไม่มีรายการ Then แสดง "ไม่มีรายการในหมวดนี้ในเดือนนี้" พร้อมปุ่ม "ล้างตัวกรอง"

**US-09 เก็บข้อมูลในเครื่อง**
- Given เพิ่ม/แก้/ลบรายการแล้ว When reload หน้า หรือปิดแล้วเปิด browser ใหม่ Then ข้อมูลยังอยู่ตรงตามที่บันทึกล่าสุด
- ไม่มี network request ใดๆ ไปยัง server ภายนอกเพื่อเก็บหรืออ่านข้อมูล (ตรวจได้จาก Network tab)

**US-10 สถานะว่าง (empty states)**
- Given ยังไม่มีรายการเลยในแอป When เปิดหน้าแรก Then ยอดทั้งสามเป็น "฿0.00" และแสดงข้อความ "ยังไม่มีรายการ เริ่มบันทึกรายการแรกของคุณ" พร้อมปุ่ม "เพิ่มรายการ"
- Given เดือนที่เลือกไม่มีรายการ (แต่เดือนอื่นมี) When เปิดหน้ารายการ Then แสดง "ไม่มีรายการในเดือนนี้"

**US-11 สัดส่วนรายจ่ายตามหมวด (แบบเรียบง่าย)**
- Given เดือนที่เลือกมีรายจ่าย When เปิดหน้าแรก Then แสดงลิสต์หมวดรายจ่ายที่มียอด > 0 เรียงจากมากไปน้อย แต่ละแถวมี ชื่อหมวด, ยอดเงิน, เปอร์เซ็นต์ของรายจ่ายรวม (ปัดเป็นจำนวนเต็ม) และแถบแนวนอนยาวตามสัดส่วน
- Given เดือนที่เลือกไม่มีรายจ่าย Then ไม่แสดงส่วนนี้ (หรือแสดง "ยังไม่มีรายจ่ายในเดือนนี้")
- Given แตะแถวหมวด Then ไปหน้ารายการโดยตั้งตัวกรองเป็นหมวดนั้น

**US-12 จัดการเมื่อที่เก็บข้อมูลใช้ไม่ได้**
- Given browser ปิดกั้น localStorage (เช่น private mode บางตัว) When เปิดแอป Then แสดงแถบเตือน "ไม่สามารถบันทึกข้อมูลในเครื่องได้ ข้อมูลจะหายเมื่อปิดหน้า" และแอปยังใช้งานได้ในหน่วยความจำ
- Given บันทึกแล้วเกิดข้อผิดพลาด (เช่น พื้นที่เต็ม) When กดบันทึก Then ฟอร์มไม่ปิด ข้อมูลที่กรอกยังอยู่ และแสดง "บันทึกไม่สำเร็จ: พื้นที่เก็บข้อมูลเต็มหรือใช้ไม่ได้"
- Given ข้อมูลใน storage เสียหาย (parse ไม่ได้/ผิดรูปแบบ) When เปิดแอป Then ไม่ crash; สำรองข้อมูลดิบไว้ที่ key สำรอง, เริ่มด้วยลิสต์ว่าง, และแสดงแถบเตือน "ข้อมูลเดิมอ่านไม่ได้ ได้สำรองไว้แล้ว"
- Given มีบางรายการผิดรูปแบบแต่รายการอื่นถูกต้อง Then โหลดเฉพาะรายการที่ถูกต้อง และข้ามรายการที่ผิด

## 4. Functional flows
**F1 — เพิ่มรายการ (US-01, US-02)**
1. ผู้ใช้กดปุ่ม "เพิ่มรายการ" (ปุ่มลอยมุมล่างขวาบนมือถือ / ปุ่มในหัวบน desktop)
2. ฟอร์มเปิดเป็น bottom sheet (มือถือ) หรือ dialog (desktop)
3. เลือกประเภท (สลับ รายจ่าย/รายรับ) → ตัวเลือกหมวดเปลี่ยนตามประเภท
4. กรอกจำนวนเงิน (แป้นตัวเลขทศนิยม `inputmode="decimal"`)
5. เลือกหมวดหมู่ (ปุ่ม/ชิปเลือกได้ทีละหนึ่ง)
6. (ไม่บังคับ) เปลี่ยนวันที่, กรอกโน้ต
7. กด "บันทึก" → validate → ผ่าน: เขียน storage → ปิดฟอร์ม → toast → ยอดและลิสต์อัปเดต; ไม่ผ่าน: แสดงข้อผิดพลาดรายช่อง

**F2 — แก้ไขรายการ (US-03)**
1. แตะรายการในหน้าแรกหรือหน้ารายการ
2. ฟอร์มเปิดโหมดแก้ไข มีค่าเดิม และมีปุ่ม "ลบ"
3. แก้ค่า → "บันทึก" → validate → อัปเดตรายการเดิม (id เดิม, `updatedAt` ใหม่)

**F3 — ลบรายการ (US-04)**
1. จากฟอร์มโหมดแก้ไข กด "ลบ"
2. กล่องยืนยัน → "ลบ" → ลบออกจาก storage → ปิดฟอร์ม → toast "ลบแล้ว"

**F4 — ดูสรุปเดือน (US-05, US-06, US-11)**
1. เปิดแอป → หน้าแรก เดือนปัจจุบัน
2. คำนวณจากรายการที่วันที่อยู่ในเดือนที่เลือก: รวมรายรับ, รวมรายจ่าย, คงเหลือ, สัดส่วนรายจ่ายตามหมวด, 5 รายการล่าสุด
3. กด ◀/▶ เพื่อเปลี่ยนเดือน → คำนวณใหม่

**F5 — ดูรายการย้อนหลังและกรอง (US-07, US-08)**
1. ไปหน้า "รายการ" (แท็บนำทางล่างบนมือถือ: "หน้าแรก" | "รายการ")
2. เลือกเดือน (แชร์กับหน้าแรก)
3. เลือกหมวดจากตัวกรอง → ลิสต์และยอดรวมหมวดอัปเดต
4. "ล้างตัวกรอง" → กลับเป็น "ทุกหมวด"

**F6 — เริ่มแอปและโหลดข้อมูล (US-09, US-12)**
1. ตรวจว่าใช้ localStorage ได้หรือไม่ (เขียน/ลบ key ทดสอบ)
2. อ่าน key ข้อมูล → parse → validate แต่ละรายการ → โหลด
3. ถ้าล้มเหลว → ทำตาม US-12

## 5. Data requirements
**Entity: Transaction**
| Field | Type | Required | Validation / notes |
|---|---|---|---|
| id | string (UUID v4) | yes | สร้างอัตโนมัติ (`crypto.randomUUID`), ไม่ซ้ำ |
| type | enum `income` \| `expense` | yes | ค่าเริ่มต้น `expense` |
| amount | integer (สตางค์) | yes | เก็บเป็นสตางค์เพื่อเลี่ยงปัญหา floating point; UI รับบาทมีทศนิยม ≤ 2 ตำแหน่ง; 1 ≤ amount ≤ 9,999,999,999 (= ฿0.01 – ฿99,999,999.99) |
| categoryId | string | yes | ต้องเป็น id ในรายการหมวดตั้งต้น และตรงกับ `type` |
| date | string `YYYY-MM-DD` | yes | วันที่ตามปฏิทินท้องถิ่น (ไม่มีเวลา/time zone); ค่าเริ่มต้น = วันนี้; ช่วงที่รับ 2000-01-01 – 2099-12-31; อนุญาตวันในอนาคต |
| note | string | no | trim ช่องว่างหัวท้าย; 0–200 ตัวอักษร; ว่างได้ |
| createdAt | string ISO 8601 | yes | ตั้งตอนสร้าง ใช้เรียงลำดับภายในวันเดียวกัน |
| updatedAt | string ISO 8601 | yes | ตั้งทุกครั้งที่บันทึก |

**Categories (คงที่ใน MVP; id ภาษาอังกฤษ, label ภาษาไทย)**
| type | id → label |
|---|---|
| expense | food → อาหาร, transport → เดินทาง, shopping → ช้อปปิ้ง, bills → บิล/ค่าน้ำไฟ, housing → ที่พัก, health → สุขภาพ, entertainment → บันเทิง, education → การศึกษา, other_expense → อื่นๆ |
| income | salary → เงินเดือน, bonus → โบนัส, sales → ขายของ, gift → ของขวัญ/ได้รับ, other_income → อื่นๆ |

แต่ละหมวดมีไอคอน (เลือกในขั้น design จากชุดไอคอนเดียว)

**Storage**
- localStorage key `expense-tracker:v1` เก็บ JSON `{ "version": 1, "transactions": Transaction[] }`
- key สำรองเมื่อข้อมูลเสีย: `expense-tracker:v1:corrupt-<timestamp>`
- มี field `version` เพื่อรองรับการ migrate ในอนาคต

**Derived values (ไม่เก็บ คำนวณเสมอ)**
- monthIncome, monthExpense, monthBalance, expenseByCategory[] ของเดือนที่เลือก
- การแสดงเงิน: `฿` + คั่นหลักพัน + ทศนิยม 2 ตำแหน่ง (เช่น ฿1,234.50)

**UI state (ไม่ต้องเก็บถาวร):** เดือนที่เลือก (`YYYY-MM`), ตัวกรองหมวด; ธีม (สว่าง/มืด/ตามระบบ) เก็บใน localStorage key `expense-tracker:theme`

## 6. Edge cases & error handling
| Case | Expected behavior |
|---|---|
| ไม่มีรายการเลย | US-10 empty state, ยอด ฿0.00 |
| เดือนที่เลือกไม่มีรายการ | ยอด ฿0.00, "ไม่มีรายการในเดือนนี้" |
| กรองแล้วว่าง | "ไม่มีรายการในหมวดนี้ในเดือนนี้" + ล้างตัวกรอง |
| จำนวน 0 / ติดลบ / ไม่ใช่ตัวเลข / ทศนิยม > 2 / เกินเพดาน | ข้อความตาม US-02, ไม่บันทึก |
| วางข้อความที่มีจุลภาค เช่น "1,250.50" ในช่องจำนวน | ตัดจุลภาคออกแล้ว parse ได้ 1250.50 |
| กรอก "0.1" + "0.2" หลายรายการ | ยอดรวมแม่นยำ (คิดเป็นสตางค์) แสดง ฿0.30 |
| ยอดคงเหลือติดลบ | แสดง "−฿x" สีเตือน |
| รายการวันที่ 31 / 29 ก.พ. ปีอธิกสุรทิน | อยู่ในเดือนที่ถูกต้อง |
| วันที่อนาคต | อนุญาต แสดงในเดือนนั้นตามปกติ |
| โน้ตยาว 200 ตัวอักษร / มีอีโมจิ / ขึ้นบรรทัด | บันทึกได้; ในลิสต์ตัดบรรทัดเดียวด้วย … ; แสดงเต็มในฟอร์ม; ข้อความแสดงเป็น text ไม่ตีความ HTML |
| เปลี่ยนประเภทหลังเลือกหมวดแล้ว | ล้างหมวด (US-01) |
| กดบันทึกซ้ำเร็วๆ (double tap) | สร้างเพียง 1 รายการ (ปุ่ม disabled ระหว่างบันทึก) |
| localStorage ใช้ไม่ได้ / เต็ม / ข้อมูลเสีย | US-12 |
| เปิดแอปสองแท็บพร้อมกัน | เมื่อแท็บหนึ่งบันทึก อีกแท็บรับ `storage` event แล้วโหลดข้อมูลใหม่ (last write wins) |
| เปลี่ยนวันข้ามเที่ยงคืนขณะเปิดแอปค้างไว้ | ค่าเริ่มต้นวันที่ในฟอร์มคำนวณใหม่ทุกครั้งที่เปิดฟอร์ม |
| รายการจำนวนมาก (เช่น 5,000 รายการ) | ยังทำงานตามเกณฑ์ §7 Performance |
| ปิดฟอร์มโดยไม่บันทึกหลังกรอกข้อมูล | ปิดได้ทันที ไม่บันทึก (ไม่มี draft) |

## 7. Non-functional requirements
- **Performance:** โหลดครั้งแรก (LCP) ≤ 2.5 วินาที บนมือถือระดับกลางเครือข่าย 4G; สลับเดือน/กรอง/บันทึก ตอบสนองใน ≤ 100 ms ด้วยข้อมูล 5,000 รายการ; bundle JS (gzip) ≤ 200 KB
- **Accessibility (WCAG 2.1 AA):** contrast ข้อความ ≥ 4.5:1; ทุกช่องฟอร์มมี label; ข้อผิดพลาดผูกกับช่องด้วย `aria-describedby`; ใช้งานได้ด้วยคีย์บอร์ดทั้งหมด (Tab/Enter/Esc ปิดฟอร์ม/กล่องยืนยัน); focus ถูกกักใน dialog และคืนเมื่อปิด; เป้าแตะ ≥ 44×44 px; รายรับ/รายจ่ายไม่สื่อด้วยสีอย่างเดียว (มี +/− และข้อความ); `lang="th"`
- **Privacy:** ข้อมูลอยู่ใน browser ของเครื่องเท่านั้น ไม่มี analytics/tracking ไม่มี request ไปบุคคลที่สาม (ยกเว้นโหลด web font ถ้าดีไซน์เลือก — ควร self-host); แจ้งผู้ใช้ในหน้า (เช่น footer/เกี่ยวกับ) ว่า "ข้อมูลเก็บในเครื่องนี้เท่านั้น การล้างข้อมูล browser จะลบรายการทั้งหมด"
- **Supported browsers/devices:** Chrome/Edge/Firefox 2 เวอร์ชันล่าสุด, Safari iOS 16+, Chrome Android 2 เวอร์ชันล่าสุด; หน้าจอกว้าง 360–1440 px; mobile-first; ไม่มี horizontal scroll ที่ 360 px
- **Localization:** UI ภาษาไทยทั้งหมด; รูปแบบวันที่ไทยปี พ.ศ. (`th-TH`); ฟอนต์รองรับภาษาไทย
- **Theme:** สว่าง/มืด ตามระบบเป็นค่าเริ่มต้น พร้อมปุ่มสลับที่มองเห็นได้
- **Tech constraint:** client-only (Vite + TypeScript + localStorage ตาม `docs/STACK.md` สำหรับแอปที่ไม่มีข้อมูลร่วม) — ไม่ใช้ Next.js/NestJS/PostgreSQL
- **Reliability:** ทุก write เป็น atomic ต่อการกระทำหนึ่ง (เขียนทั้งก้อนครั้งเดียว); ไม่ crash เมื่อ storage ผิดปกติ (US-12)

## 7b. Look & feel
จาก `docs/IDEA.md` ส่วน "Look & feel" (คัดลอกตามต้นฉบับ):
> ให้ AI เสนอ 3 แบบ

รายการที่ไอเดียไม่ได้ระบุ:
- ผู้ใช้/บริบท: ไม่ได้ระบุ (อนุมานจากไอเดีย: คนเดียว จดบนมือถือระหว่างวัน)
- ความรู้สึกที่ต้องการ / ไม่ต้องการ: ไม่ได้ระบุ
- เว็บอ้างอิงและสิ่งที่ชอบ: ไม่ได้ระบุ
- Anti-references: ไม่ได้ระบุ
- ลำดับความสำคัญของหน้า: ดู §7c (อนุมาน)
- สี/ฟอนต์/โลโก้: ไม่ได้ระบุ (ต้องใช้ฟอนต์ที่รองรับภาษาไทย)
- ธีม: ไม่ได้ระบุ (PRD กำหนดสว่าง/มืดตามระบบ + ปุ่มสลับ)
- ความหนาแน่น: ไม่ได้ระบุ
- กราฟ: ไอเดียระบุ "ไม่ต้องมีกราฟซับซ้อน" → มีเพียงแถบสัดส่วนรายจ่ายตามหมวด (US-11)
- ข้อมูลตัวอย่าง (demo data): ไม่ได้ระบุ
- เกณฑ์ยอมรับด้านภาพ: ไม่ได้ระบุ

**คำสั่งต่อขั้น design:** เสนอ 3 แนวทางภาพที่แตกต่างกันชัดเจน (สี, ฟอนต์ไทย, ความหนาแน่น, บุคลิก) ให้มนุษย์เลือกหนึ่งแบบ — ดู Open questions Q1

## 7c. Key pages
1. **หน้าแรก (สรุปเดือน)** — สำคัญที่สุด ต้องสวยที่สุด: ตัวเลือกเดือน, การ์ดยอดคงเหลือ (เด่นสุด) + รวมรายรับ + รวมรายจ่าย, สัดส่วนรายจ่ายตามหมวด, 5 รายการล่าสุด, ปุ่มเพิ่มรายการ
   - Charts: ต้องการเพียงแบบเรียบง่าย — รายจ่ายตามหมวด เหมาะกับ **แถบแนวนอนเรียงจากมากไปน้อย** (horizontal bar list พร้อม % และยอด); รายรับเทียบรายจ่ายของเดือน แสดงด้วยตัวเลขในการ์ดก็พอ (ถ้าจะมีภาพ ใช้แถบเปรียบเทียบสองแท่งได้) — ไม่มีกราฟเส้น/หลายเดือน
2. **ฟอร์มเพิ่ม/แก้ไขรายการ** — ใช้บ่อยที่สุด ต้องเร็วและกดง่ายด้วยนิ้วโป้ง: ช่องจำนวนเงินตัวใหญ่, สวิตช์ประเภท, ชิปหมวดพร้อมไอคอน
3. **หน้ารายการย้อนหลัง** — ตัวเลือกเดือน, ตัวกรองหมวด, ยอดรวมของตัวกรอง, ลิสต์จัดกลุ่มตามวัน

## 8. Success metrics
- ผู้ใช้ใหม่เพิ่มรายการแรกได้ภายใน 30 วินาทีโดยไม่ต้องอธิบาย (ทดสอบ usability 3–5 คน)
- เพิ่มรายการทั่วไป (จำนวน + หมวด + บันทึก) ใช้ ≤ 4 การแตะหลังเปิดฟอร์ม และ ≤ 10 วินาที
- ยอดรวมรายรับ/รายจ่าย/คงเหลือถูกต้อง 100% ในชุดทดสอบ QA (รวมกรณีทศนิยม)
- ข้อมูลไม่หายหลัง reload ในทุก browser ที่รองรับ (QA ผ่าน 100%)
- Lighthouse mobile: Accessibility ≥ 95, Performance ≥ 90

## 9. Open questions
- **Q1 (Look & feel):** ไอเดียขอให้ "AI เสนอ 3 แบบ" แต่ไม่ระบุความรู้สึกที่ต้องการ เว็บอ้างอิง หรือสี — มีเว็บ/แอปอ้างอิงหรือความรู้สึกที่อยากได้ไหม (เช่น อบอุ่นเป็นกันเอง / เรียบหรูแบบแอปธนาคาร / สดใสสนุก)? ถ้าไม่ตอบ ขั้น design จะเสนอ 3 แนวทางที่ต่างกันให้เลือก
- **Q2:** ยอดคงเหลือคิดเฉพาะเดือนที่เลือก (รายรับ − รายจ่ายของเดือนนั้น) ไม่ยกยอดสะสมจากเดือนก่อน — ถูกต้องไหม?
