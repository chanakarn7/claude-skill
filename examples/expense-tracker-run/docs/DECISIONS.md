# Decisions log

## Stage 1 — Requirements (BA)
- [ba] Client-only SPA (Vite + TypeScript + localStorage), no backend/auth — why: idea says no login, no server, single user; STACK.md says client-only apps ignore the default server stack — alternatives: IndexedDB, Next.js+API per STACK.md
- [ba] Amounts stored as integer satang; ฿0.01–฿99,999,999.99, max 2 decimals — why: avoid floating-point sum errors; sane personal-finance ceiling — alternatives: float baht, decimal library
- [ba] Fixed default category set (9 expense, 5 income), no custom categories in MVP — why: idea only gives examples; keeps MVP small — alternatives: user-editable categories, free-text category
- [ba] Monthly balance = income − expense of the selected month only (no carry-over) — why: idea says summary "ของเดือนที่เลือก" — alternatives: running cumulative balance
- [ba] Simple expense-by-category horizontal bar list on home (US-11) — why: idea excludes only "complex" charts; a summary page benefits from a simple breakdown — alternatives: no visualization, pie chart
- [ba] Thai dates in Buddhist Era (th-TH locale, e.g. "ตุลาคม 2569") — why: Thai-language UI for Thai users — alternatives: Gregorian year
- [ba] Future dates allowed; date range 2000-01-01 to 2099-12-31 — why: users may log scheduled income/expenses; bounds catch typos — alternatives: block future dates
- [ba] Editing/deleting via tapping an item → edit form with Delete + confirm dialog — why: simple, mobile-friendly, testable — alternatives: swipe-to-delete, undo toast instead of confirm
- [ba] Light/dark following system with a visible toggle — why: STACK.md theming convention; idea is silent — alternatives: light only
- [ba] Prototype: skip (3 screens, simple flows); 3 visual directions to be proposed in design stage — why: ba-agent rule for ≤3 screens; idea's "AI เสนอ 3 แบบ" can be satisfied at design stage — alternatives: include prototype
- [ba] Corrupt storage is backed up to a separate key and app starts empty with a warning; invalid individual records skipped — why: never crash, never silently destroy user data — alternatives: block app with error screen
- [ba] Multi-tab: reload on `storage` event, last write wins — why: cheap consistency for a single user — alternatives: ignore multi-tab
- [ba] Demo data only via a demo-only path, never in normal use — why: pipeline needs demo data; real users start empty — alternatives: preload sample data on first run
- [ba][DEVIATION] Custom categories, search in notes, budgets, recurring items, PWA install excluded — why: not in idea; MVP scope — alternatives: add later via change request


## Stage 2 — Technical blueprint (SA)
- [sa] ADR-1 Client-only SPA: Vite + React 19 + TypeScript strict, static output, no backend — why: PRD §1/§7, IDEA "ไม่ต้องมี login ไม่ต้องมี server"; STACK.md client-only rule — alternatives: STACK.md monorepo (Next.js + NestJS + PostgreSQL), vanilla TS
- [sa] ADR-2 localStorage single versioned JSON document `expense-tracker:v1`, whole-document write per change — why: PRD §5; 5,000 rows ≈ 1.3 M UTF-16 units of ~5 M quota; one setItem = atomic — alternatives: IndexedDB, one key per record
- [sa] ADR-3 Money as integer satang, string-based parsing (no float math) — why: PRD §5 and 0.1+0.2 = ฿0.30 — alternatives: float baht + rounding, decimal library
- [sa] ADR-4 shadcn/ui + Tailwind v4 (@tailwindcss/vite) + lucide-react; US-11 bars in plain CSS (no recharts); hash routing without a router library — why: STACK.md UI layer; PRD bundle ≤200 KB and only a simple bar list (STACK.md allows CSS bars for that) — alternatives: recharts, react-router
- [sa] Target machine not stated (idea predates intake template; no Tech stack/server/เกณฑ์ผ่าน sections) → assumed: mid-range phone browser per PRD §7, static files on any static host; acceptance table built from PRD §7/§8 measurable criteria — why: client-only app needs no server sizing — alternatives: assume Raspberry Pi host from STACK.md (only relevant to devops serving static files)
- [sa] shadcn components added: button input textarea label dialog sheet alert-dialog toggle-group select sonner card badge alert; STACK.md's table/tabs/dropdown-menu/tooltip not added — why: no screen uses them — alternatives: install the full STACK.md list
- [sa] Fonts self-hosted via @fontsource (Thai + Latin subsets, ≤3 weights); family chosen in design stage — why: PRD §7 Privacy (no third-party requests) and LCP — alternatives: Google Fonts link
- [sa] State in React context + useReducer; derived totals via useMemo, never stored — why: two screens, one store — alternatives: Zustand, Redux
- [sa] Production CSP meta with `connect-src 'none'` — why: enforces US-09 "no network requests" and limits XSS impact — alternatives: no CSP, host-set header only
- [sa] Demo data via `?demo=1`, memory only (storage never read or written in demo mode); same generator gives the 5,000-row perf fixture — why: DECISIONS stage 1 "demo-only path, never in normal use"; protects real data — alternatives: separate demo storage key, preload on first run
- [sa] Corrupt/partly-invalid storage: back up raw value first, then rewrite main key (empty or valid-only); if the backup write fails, leave main key untouched and run memory-only with the "unavailable" banner — why: US-12 + stage-1 "never silently destroy user data"; avoids a new backup on every reload — alternatives: never rewrite main key until the first user save

- [sa] App scaffolded at repo root via a temp dir copy (create-vite `--overwrite` would delete docs/) — why: `npm run demo` at repo root per STACK.md — alternatives: app/ subfolder with root proxy scripts
- [sa] No backup/export: clearing browser data loses everything; only automatic copy is the corrupt-* key; no in-app export (PRD non-goal, Q4 still open) — why: PRD §1 non-goals — alternatives: JSON export (needs PRD change)

## Stage 3 — Design (designer)
- [design] No Look & feel given (IDEA "ให้ AI เสนอ 3 แบบ", PRD §7b/Q1) → wrote docs/DESIGN_OPTIONS.md with three directions: Banknote, Night Market, Plain Ledger; `Chosen: Banknote` — why: idea delegated the choice; human can switch the `Chosen:` line at the design gate
- [design] Banknote (bottle green #1E5A43 + marigold #F2B53A on paper #FAF7F0; dark #101613) — why: strongest identity that still fits a daily mobile money app for a general Thai audience; single-hue bars stay color-blind-safe; brick-red slab gives negative balance a second cue beyond "−" — alternatives: Night Market (neon, per-category hues, hard to keep 14 colors distinct/CVD-safe), Plain Ledger (dense navy table, safest but generic)
- [design] Signature element: the Banknote slab (green balance card, inset frame, marigold ฿ seal; turns #7A2318 brick with a "ติดลบ" badge when negative), echoed by a marigold FAB — why: designer rule requires one signature; puts the eye on the balance (PRD §7c home "การ์ดยอดคงเหลือ (เด่นสุด)")
- [design] Fonts Prompt 500/600 (headings, buttons, all money figures, tabular-nums) + Sarabun 400 (body), self-hosted via @fontsource thai+latin subset files imported in src/main.tsx (3 weights total) — why: both cover Thai incl. ฿; PRD §7 Privacy (no third-party requests); SA ≤3 weights — alternatives: IBM Plex Sans Thai only, Noto Sans Thai only
- [design] Category icons fixed (lucide): food UtensilsCrossed, transport Bus, shopping ShoppingBag, bills Receipt, housing BedDouble, health HeartPulse, entertainment Clapperboard, education GraduationCap, other_expense CircleEllipsis, salary Wallet, bonus Trophy, sales Store, gift Gift, other_income CircleEllipsis — why: contract `Category.icon` is "final pick in design stage"; House reserved for nav
- [design] Theme toggle = 3-item ToggleGroup (Sun/Moon/Monitor) in the header on every page; dark tokens duplicated under `@media (prefers-color-scheme: dark) :root:not(.light)` to avoid a flash because the CSP forbids an inline theme script — why: PRD §7 visible toggle; SA CSP `script-src 'self'` — alternatives: dropdown-menu (not installed), single cycling button (state less visible)
- [design] Expense amounts in ink (foreground), never red; red only for errors and the negative-balance slab; income in green with "+" — why: avoid alarming ordinary spending; PRD §7 "not by color alone" covered by +/− and labels
- [design] Income vs expense shown as numbers only (slab + ledger card); expense-by-category as a CSS horizontal bar list, single hue, width = share of month expense — why: PRD §7c says numbers suffice; SA ADR-4 no chart library
- [design] Screens: home, entry-form, list, delete-confirm, storage-alerts (5); all US-01..US-12 covered — why: overlays and US-12 states get their own ids so proto and screenshots can show them
- [design] Small UI choices not fixed by the PRD: toast 2.5 s bottom-center (PRD ≤3 s); corrupt-data banner dismissible for the session, unavailable banner persistent; delete confirm initial focus on "ยกเลิก"; list shows "n รายการ" when unfiltered; after delete focus moves to the page heading — why: safest defaults; none contradicts a PRD statement
